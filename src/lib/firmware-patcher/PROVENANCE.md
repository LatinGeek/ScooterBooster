# Firmware Patcher — provenance

## Upstream

| Field                 | Value                                                            |
| --------------------- | ---------------------------------------------------------------- |
| Repository            | https://github.com/scooterteam/bw-patcher                        |
| Version               | 1.1.6                                                            |
| Commit                | `95a8f339787a1fb6486554d61b573b8e2b688c53` (2026-09-28)          |
| Licence               | CC BY-NC-SA 4.0 (see the upstream `LICENSE`)                     |
| Reference environment | Python 3.14.4, keystone-engine 0.9.2, capstone 4.0.2, crcmod 1.7 |

The port is a behavioural reimplementation. No upstream source file is vendored, and no
GPL/native assembler or disassembler is linked at runtime:

- `core.py`, `core_lks32.py`, `core_es32.py`, `core_n32.py`, `modules/leqi_speed.py` and the
  eleven `modules/*.py` patchers are ported to TypeScript with the same signatures, constants,
  patch names, offsets and return shapes.
- The Thumb encoder (`assembler/thumb.ts`) and the narrow decoder (`assembler/decoder.ts`) are
  first-party. The encoder is verified byte-for-byte against keystone 0.9.2 by
  `assembler/__fixtures__/keystone-goldens.json` (7 405 vectors, 3/3 tests).
- CRC-16/CCITT, LKS32 CRC-32 and N32 CRC-16 are first-party table/bit implementations in
  `crc.ts`, cross-checked against `crcmod` and `core_n32.py`.

## Generated capability matrix

`capabilities.ts` is generated by introspection of the pinned Python classes and upstream
`app.py`, not from the README:

```sh
python scripts/firmware-parity/gen_capabilities.py \
  --ref <bw-patcher @ 95a8f33> \
  --manifest scripts/firmware-parity/fixture-manifest.json \
  --out src/lib/firmware-patcher/capabilities.ts
npx prettier --write src/lib/firmware-patcher/capabilities.ts
```

`mss0exp` is appended manually because it is a ScooterBooster custom patch (SPEC §4.7).

## Firmware fixtures

Genuine binaries are **never committed**. `scripts/firmware-parity/fixture-manifest.json`
records their paths (outside the repo) and SHA-256:

| Fixture          | SHA-256                                                            | Size    |
| ---------------- | ------------------------------------------------------------------ | ------- |
| mi6 base factory | `31362a4863d3430fdd90812fe175a4b37e9f426207ce804afeeba0f6432e4a2b` | 148 108 |
| mi6 lite factory | `83d3d3c05cce80be5d0f1e42046b9b792423beec2d5e6e96af873d8c5c3a4d7d` | 81 096  |

Only these two models have genuine fixtures. The other nine ports are marked
`verification: "synthetic-only"` in the matrix and stay hidden under SPEC G5; synthetic
vectors (if produced) are never shipping evidence.

## `mss0exp`

The custom MSS0 coherent-latch patch integrates the read-only experiment under
`D:\Coding\Firmware disassembling` (SPEC §4.7). Reference documents:

- `docs/research/mi6-base-mss0-coherent-latch.md` / `.json`
- `docs/research/mi6-lite-15-25-35-mss0-coherent-latch.md` / `.json`

The engine only encodes the final body bytes listed in SPEC §4.7; it does not read or copy any
firmware binary at build time or runtime.

## Parity

```sh
BW_PATCHER_REF=<clean bw-patcher @ 95a8f33> \
BW_PATCHER_PYTHON=<python with keystone/capstone/crcmod> \
npx tsx scripts/firmware-parity.ts --out tmp/firmware-parity-report.json
```

The harness compares detection, the ordered patch log and the output SHA-256 against the pinned
Python reference. Missing fixtures or interpreter/deps yield `UNVERIFIED`, never `PASS`.
Real-fixture parity for `mi6`/`mi6lite` is green (18/18 comparisons).
